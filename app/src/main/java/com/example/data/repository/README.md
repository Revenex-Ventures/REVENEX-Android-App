# data/repository/

Contains the central repository singleton and the static sample data seed.

## Files

### `ErpDataRepository.kt`

The single source of truth exposed to all UI screens. It is a singleton accessed via `getInstance()`.

**Key responsibilities:**

- Exposes all app state as `StateFlow<T>` properties (students, teachers, attendance, fees, notices, etc.).
- `bindDataSource(source: ErpDataSource)` — launches coroutine collectors that pipe each data source `Flow` into the repository's `MutableStateFlow`s. Called internally whenever the data mode changes.
- `setDataMode(mode: DataMode)` — switches between Demo and Production. Cancels the old collectors, creates the appropriate `ErpDataSource` implementation, and rebinds. This eliminates any dual-write race conditions on mode switch.

**Business logic included in the repository:**

| Method | Description |
|---|---|
| `loginWithFirebase(email, password)` | Full Firebase Auth login; reads custom JWT claims (`role`, `schoolId`, `employeeId`, `studentId`, `studentIds`) to build the correct `UserProfile` |
| `recordRollCallSession(record)` | Saves an attendance session and writes an `AuditLogEntry` |
| `processInvoicePayment(invoiceId, amount)` | Records a fee payment and generates an audit trail entry |
| `calculateStudentAttendancePercentage(studentId)` | Computes real attendance % from all stored `ClassAttendanceRecord`s |
| `uploadAttachment(uri, folder)` | Delegates to `FirebaseStorageManager` in Production; throws in Demo |
